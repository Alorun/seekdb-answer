## 为什么 28.5 不是“材料结构错”

当前 26 单元自评 raw 44.0，平台 28.5，约 65% 兑现。结构检查全部通过（v3-clean）：
2.0 都有 transfer/limitation、summary 存在、无本地分数、pointer 精确。差距主要来自
**每个实例的证据链质量**：现有单元很多是“我先计划 → 实测结果”，缺少
**学生先提出错误假设/预测 → 独立实验推翻 → 修正/回退 → 复测 → 迁移/局限** 的闭环。
平台榜首 67 说明它有很多这种完整链路；单纯把同样的句式加长不会涨到 67。

## 扩到 40+ 单元的原则

1. 每个新单元必须是**独立问题**，不能是已有单元换词；结果 evidence 是新的命令输出。
2. 每个 2.0 单元必须有：student 的假设/预测 → 实验 → 结果 → 修正/回退 → 复测 →
   迁移到新场景 → 局限；1.5 单元至少有“假设 → 实测推翻 → 修正/回退”。
3. 新增重点放在**负结果与修正链**：这是本轮真实做过、且现有 26 单元覆盖不足的部分。
4. 仍然 v3-clean：无本地 0–100 分数、无 `E=`、pointer 精确、≤240 字符、128 KiB 上限。
5. 目标规模 41 单元左右（26 + 15），自评 raw ~70；材料预计 75–80 KB，留出余量。

## 性能下一步：先要 T/B/M

E=4706.698345 的 +258 已经兑现，但“安全 exact 微调”最多再给 +50–150；
770 的差距不可能靠 q7 扫描的 2–3% 微调补上。需要平台页面的 **T_write / T_query / B / M**
四个分项：

- 若 **T_query** 是主短板：安全 exact 已在地板，下一步只有 float32 误差带/AVX/查询批处理；
  AVX 是 f3fb066 的 0 分路径，不碰；float32 本地只有 3%，不建议。
- 若 **M** 是主短板：row arena/紧凑行可省 1–2 MB，约 +50–150。
- 若 **B** 是主短板：当前 B=5.26 MB 已接近 5.12 MB 原始向量，空间小。
- 若 **T_write** 是主短板：解析/编码快路径约 +10–30，或依赖驱动流水线的组提交。

**在拿到 T/B/M 前，不再盲目改 exact 热路径**；prompt 的 15 个新单元是期望收益更高、
风险更低的方向。
